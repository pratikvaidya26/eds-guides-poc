If your systems do not use Secure Boot, you do not have to download and enroll the public keys and perform any additional steps.</p></li></ul><p class="- topic/p ">Even if the kernel modules included in the InfoScale packages are digitally signed, there is no change in the InfoScale deployment process if Secure Boot is disabled.</p><ul class="- topic/ul "><li class="- topic/li "><p class="- topic/p ">In case of upgrades, for upgrades from an InfoScale version that does not support Secure Boot, you can proceed with the upgrades directly. No additional steps are required, presuming that you do not want to enable Secure Boot on your systems.</p></li></ul><p class="- topic/p ">If you want to use Secure Boot in such an environment, then you must first upgrade InfoScale to the latest version. You can then enable the Secure Boot feature on all the systems. Once Secure Boot is enabled, you must download and enroll the InfoScale public key on each system.</p><ul class="- topic/ul "><li class="- topic/li "><p class="- topic/p ">This feature is supported on Linux platform only.</p></li></ul><p class="- topic/p ">The supported operating systems are RHEL 9, RHEL 10, and SLES 15.</p><ul class="- topic/ul "><li class="- topic/li "><p class="- topic/p ">The InfoScale public keys are valid for 2 years. Key expiry does not hamper any existing functionality in your production environment. However, you cannot install any new additional InfoScale packages that include signed kernel modules after the keys have expired. To do so, you must obtain new keys from the InfoScale website and enroll them on your InfoScale systems.</p></li><li class="- topic/li "><p class="- topic/p ">InfoScale installation fails if Secure Boot is enabled but the InfoScale public key is not enrolled on the systems.</p></li></ul><p class="- topic/p ">Similarly, after a successful InfoScale installation, if the InfoScale public key is deleted from the system, the InfoScale kernel modules fail to load and display a daemon error.</p><p class="- topic/p ">For example, the following error appears on the terminal when you try to load the <codeph class="+ topic/ph pr-d/codeph ">vxvm</codeph> module:</p><codeblock class="+ topic/pre pr-d/codeblock " xml:space="preserve" outputclass="txt">VxVM vxdisk ERROR V-5-1-684 IPC failure: Configuration daemon is not accessible</codeblock></body></topic>
